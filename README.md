# 文青尚品

本机桌面 APP，使用已有抖店 Playwright 执行器读取本机 Excel 和素材，逐店、逐商品保存草稿。运行不依赖 Workbuddy、Codex、模型接口或系统 Node.js。

当前 Mac 版本 **v0.4.11-alpha**，支持拼多多可切换类目新模板、富文本实际值和按类目忽略不适用字段；素材区可导出两种空白模板。普通商品失败仅在执行器确认未开始保存且店铺仍匹配后跳过，关键异常或结果未知仍停批。拼多多完整核对在保存前完成，保存后只确认本次成功提示，不再重新打开草稿复核。修复新建拼多多款式时异步名称校验清空备注：先填写备注再填写名称，保留原表和选填规则，无额外固定等待。修复预售时间等下拉选项被列表裁剪或底栏遮挡：打开前留出空间，列表内滚动、稳定命中后精确选择。拼多多主图一次多选，Windows新测试包详情分批多选，逐位置内容核对；商品视频在进入编辑页后优先启动，后台上传时继续填写表格，全部完成后才能保存草稿。保留一键编号、按钮旁选择唯一首图和同店同页复用。Windows已提供v0.4.14-alpha x64共用测试包（Windows短路径缓存、详情最多5张分批、浏览器字节/尺寸诊断），含Ego安装引导器、一键配置CMD及两个商品模板素材库；2026-10-24已收到用户Windows实测成功反馈，具体系统及完整运行报告未取得。拼多多当前范围是时尚套装、毛衣/针织衫，原图循环为10张主图、固定17张详情和时段预售，真实验证范围详见[检查记录](APP检查记录.md)。抖店既有范围为时尚套装、针织衫/毛衣/羊毛衫，5张主图、现货预售混合。

新增主图一键编号、原图备份与失败恢复，后台防休眠、托盘与系统状态通知，以及执行器按需加载。详见 [更新与检查说明](优化与Windows交付说明.md)。

## 直接使用 Mac APP

1. 打开 `文青尚品.app`。抖店需 Google Chrome；拼多多需安装 ego lite 并完成首次设置，无需填写端口。
2. 添加后台显示的完整店名。抖店点击“登录”进入专用 Chrome；拼多多点击“连接 Ego”进入本店工作空间并人工登录，再返回 App 点“核对”。每店使用独立资料目录；APP不会复制其他浏览器的 Cookie。
3. APP自动检查已登记窗口，也可点击“刷新状态”或“核对”。页面实际店名必须精确一致，不能用“浏览器已打开”代替核对成功。
4. 点击“选择文件夹”，选择总素材库。一级子文件夹各代表一个商品。抖店读取 `商品信息/商品信息.xlsx`；拼多多的Excel也可放商品根目录、商品信息或商品资料目录，主图支持“主图”“轮播图”等目录名。错误显示到商品、字段或路径，不猜填。
5. 勾选店铺和商品，检查本批素材，确认完整的商品 × 店铺任务清单，再开始。新增店铺不会默认全选。
6. 在运行记录查看结果。只有取得保存成功证据才标为“已保存草稿”。

**仅保存草稿，不提供正式发布。** 验证码、安全限制或权限拒绝会停止整批并保留 Chrome；人工处理后需重新核对。APP不解验证码，不伪装浏览器，不自动绕过或恢复。暂停、停止和正常退出以当前商品为边界，避免在保存中途杀进程。

默认根据本机已确认历史跳过，跳过不算本次新保存；这不是后台草稿存在性查询。后台删除草稿后，如需再测试，点击“重新创建草稿”，核对完整清单后确认。新的一批分配独立执行记录，旧回执保留；后台旧草稿若未删除会同时存在。普通启动仍会被未知结果阻断；明确点击“重新创建草稿”并确认后，旧待核实和已有草稿不拦截独立新任务。原页面和回执保留，后台原草稿可能仍在。不要删回执或更换任务目录。崩溃重启保留待核实记录。

每店保留独立登录环境。同一个账号拥有多家店时，首次登录可能进入平台默认店；以窗口头部实际店名为准，身份不符会显示并阻断。可在该店独立窗口人工选择目标店，或通过“重新登录”建立新的独立环境；原环境保留，不退出其他店。APP重开只检查登记的窗口，不扫描所有浏览器，不自动重新登录。

每店新增一个APP专用工作标签页，后续商品与批次均复用它。取得保存成功证据后，在同一页进入独立新建商品流程，检查没有前商品标题、主图、价格、商家编码再填写，不直接刷新已存草稿。普通启动遇到未知结果或安全拦截停批保留页面。明确重建时保存旧记录和证据，沿用本店工作页进入空白新建；拼多多保存成功后结束本商品，下一商品仍复用此页，避免页面累积占满。旧版遗留和用户手工打开的页面不会自动关闭；固定工作页不要手工复制或用来编辑其他商品。

Excel 中商家编码由用户提供，原样保留，不自动生成。价格只读现有统一售价及个别尺码调整；组合件数、年龄、风格及“对应主图编号”继续使用原字段。没有另造一套 APP 商品模板。

## 拼多多精简表读取

拼多多商品级“商品编码”自动沿用基础信息的“商品货号”，无需重复填写；旧表没有货号时兼容原“商品编码”。“商品参考价（元）”由用户按真实信息填写，每次扫描和运行前重新读取，不固定为测试价，也不根据售价推算。SKU规格行编码保持原规则。

按字段名及列标题读取，删空行、移动行列和修改样式不会改变含义。基础信息与服务使用“字段/填写值”列；款式与尺码按各自表头识别，不固定在第14行。旧表兼容，不要求恢复系统控制行或选填调整表。数据列重名、真实价格/库存缺失或无法唯一识别数据时明确提示，不猜值。每款不同价格仍由原统一价格及选填调整提供。

满件折扣在已核对后台固定为满2件，表中只保留“折扣（几折）”9.5即可；旧显式开关仍可读取，实际页面不支持的停用会明确提示。针织衫在基础信息填“材质成分”，格式如“涤纶40%；腈纶60%”（仅格式示例），不能把区间猜成具体含量。套装继续读取原材质与成分区间。

## 拼多多选填资料与素材

按当前时尚套装后台的红色星号区分必填，“重要”是推荐提示。品牌、风格等选填属性留空不阻断；白底图、包装标签图、视频、长图等有合格素材就使用，没有就跳过，不要求先建空目录。选填文件损坏、比例不合要求或同类单图有多份时显示提示并跳过该项；不修改原图。主图、标题、材质/成分含量、价格、库存及当前类目的必填服务仍须完整，网页实际新增必填项时停止并提示。

主图原图自动循环为10张；详情仍为17张：有尺码图时首位放一张，其余用详情图及主图轮询补齐；没有尺码图或详情图也可只用主图补齐。主图按文件名自然排序，不要求先改成01～10。规格编码、预览图与启停状态留空时保留平台状态，不自行生成编码。

## 实时运行日志

批量上架页在执行中显示步骤开始、完成耗时、脚本输出与报错；展开“查看完整日志”后继续实时更新。默认跟随最新日志，向上阅读时保留位置。拼多多通过本地逐行事件记录传递进度，避免Ego控制台缓冲到任务结束才显示；同一事件不会重复展示。

主图显示服务端完成数量与等待时间，详情显示批量完成数量，视频每10秒提示平台处理状态。上传超时保留现场；显式重建仍可建立独立新任务，旧记录不删除。

## 数据存放

APP配置、运行记录和每店浏览器资料在 macOS 用户的应用数据目录（`~/Library/Application Support/文青尚品/`），素材留在你选择的原目录。换电脑需重新选择本机素材库、添加店铺并登录，不复制 Cookie。

- `config.json`：路径、店铺与勾选项；每次打开重新核对登录状态。
- `tasks/`：按店铺ID、商品ID、内容版本归档；`attempts/<执行ID>/` 保留各次新建的意图和回执，兼容旧版原目录。
- `runs/`：不可随当前选择改变的批次快照与日志。
- `browser-profiles/`：独立 Chrome 登录资料。关闭 APP 不关闭这些浏览器。

本机依赖 Chrome 和正常平台访问；去掉智能体调度不会让网络上传自动变快。首版本机包仅做开发签名，未做外部分发签名、公证和自动更新，不是已验收的 Windows 安装包。

## 开发与检查

仓库：https://github.com/pawnone/lsxgit 。源码开发需 Node.js 22.12 或以上。

```sh
npm ci
npm start
npm run check
npm test
npm run test:native
npm run test:workspace
npm run build:mac
npm run build:win
node scripts/check-rename-native.mjs
node scripts/check-category-entry.mjs
node scripts/check-category-attributes.mjs
node scripts/check-service-fields.mjs
```

`npm start` / `npm run app` 打开真实 Electron APP；`build:mac` 使用当前 Mac 架构生成 `release/文青尚品-darwin-arm64/文青尚品.app`（Apple芯片）。运行产物已包含 Electron 的 Node 运行时及生产依赖。

`npm run test:native` 使用临时、独立的测试数据目录验证实际原生 APP，无真实店铺写入。可通过 `WQ_TEST_APP` 指向打包后的可执行文件，通过 `WQ_TEST_MATERIALS` 指向本机素材库增加只读 Excel/图片检查；不把这些本机路径写进项目配置。`node scripts/check-safety.mjs` 仅在本地模拟页面验证安全停止和浏览器保留。

早期外观 Demo 仍保留：`npm run demo` 启动网页，`npm run build:demo` 生成静态文件；`npm run test:ui` 检查模拟交互。Demo不是实际执行入口，不能将其模拟结果当作真实草稿回执。

```text
desktop/            Electron主进程、隔离preload、任务服务、原生页面与worker
engine/doudian/     既有0.2.17执行器的集成快照及来源哈希
scripts/            打包、语法、原生APP及本地安全检查
test/               多店队列、身份/资料/安全门禁、恢复与重复保护测试
demo/               早期交互原型及共享图标/样式
```

检查结果与限制见 `APP检查记录.md`；版本见 `CHANGELOG.md`。不提交密码、Cookie、登录资料、真实 Excel、视频、回执或本机配置。第三方许可见 `THIRD_PARTY_NOTICES.md`。

## 针织衫模板

新模板将商品属性集中到“基础信息”：第4–21行为原有必填字段，第22–49行为28项针织衫选填属性，不再增加独立工作表。四列为字段名称、填写内容、填写要求、填写说明。按真实商品填黄色格；必填/选填提示不能代替脚本校验。类目仍由基础信息中的完整类目路径确定。

旧套装Excel继续兼容；旧针织衫分表模板仍可读取，同一文件不能同时出现两份属性。合并前后标准化商品数据一致，原值不自动修改。材质仍限单项100%。2026-10-21已用独立本地脚本在星怡严选女装完整保存1份针织衫草稿，5个SKU编码、价格、库存回读一致；相同执行代码同步到Mac。运费、售后按Excel主动选择并回读；选填属性的全部组合与Windows仍未实测。

## 拼多多编号与首图（0.4.4）

商品行保留“一键编号”和“首图”缩略图按钮。编号直接备份并处理文件，同时修正SKU图片引用；首图按钮旁展开一排缩略图，选一张并点“确认首图”即可收起，不切换页面或打开大抽屉。

只维护基础信息的一格“首图编号”，由App写回原Excel。轮播第一张和详情尺码表之后的第一张商品图使用同一张；没有单独详情首图选择。选择不会改文件名，重新编号也保持SKU指向原图片。仅编号不会擅自新增首图配置，未配置的旧表仍兼容原有详情。

设置后通常只需5张原图，循环上传10张主图、17张详情；尺码图有则第一位放一次。白底、标签和视频仍选填，不需要专门的详情目录。重复上传所需临时副本放任务缓存，不向素材库复制凑数。

资料抽屉点击左侧遮罩或按Escape可关闭，关闭键固定顶部；查看图片计划不会修改商品表。

### 拼多多商品表

基础信息选择时尚套装或针织衫，程序按实际选择匹配已适配的类目；不靠单元格颜色或公式缓存判断。非当前类目字段保留在表中并变灰，输入校验限制直接输入；粘贴可能绕过，执行器仍忽略这些字段。商品类型切换不改标题、价格或款式，缺少新类目必填数据时集中提示。说明、颜色及字体不参与商品指纹；冻结后任何源文件变化仍须重新预检。

新类别需要补充字段规则和网页控件适配，不能仅增加Excel行就自动运行。当前阶段仅验收拼多多素材库的套装、单上衣两个商品；抖店和Windows后续另行更新。

Windows交付操作见[Windows交付与环境配置](Windows交付与环境配置.md)：完整解压后运行“一键配置环境.cmd”，已有Ego跳过安装，没有则使用用户提供的安装引导器。首次引导和商家登录由用户完成；命令及接口检查通过后才创建快捷方式并启动App。Mac安装版本未随Windows交付更换。
