# 拼多多 Mac App 接入（v0.4.7-alpha）

2026-10-21 用户更正顺序：先接入文青尚品并更新 Mac，由用户手动发起商家测试。2026-10-22起按真实失败现场修复并检查后续步骤；最新实测范围见根目录APP检查记录。Windows 本次未更新。

## 来源与依赖

用户指定主脚本是 WorkBuddy `pdd-auto-listing/run-full.mjs`（文件头 v2.1、包版本0.3.1-local-review）；v0.1.2仅表示数据读取核心。core三文件保持原字节，来源哈希见UPSTREAM.json。读取 Excel 使用ExcelJS 4.4.0（MIT），图片尺寸使用image-size 2.0.4（MIT），抖店继续使用Playwright Core 1.64.0（Apache-2.0）。

拼多多按用户要求改用已安装的ego lite，调用官方ego-browser CLI及其Page API；开源SDK来源citrolabs/ego-lite（MIT），浏览器二进制另行安装，不把SDK开源许可等同于二进制分发许可。App自带Node读取Excel，不需要Codex、WorkBuddy或模型接口。Ego子进程只接收主进程生成的固定操作与JSON数据；渲染页不提供Shell、端口或代码入口。

## 流程

平台切换保存各自素材根目录并清除跨平台选择。每店一个以工作标识命名的Ego空间，连接按钮交回人工登录，核对时精确检查所有本空间拼多多页的完整店名；不匹配或多店名阻断。刷新不会自动接管用户持有的空间。页面运行中被用户接管、验证码或权限拒绝立即停止，不重试接管。

run-draft.mjs编排空白入口、精确推荐类目、属性、规格备注、双价库存编码状态、尺码表停用、全部素材、服务运费、保存前最终复核、保存意图及本次保存成功提示确认。当前仅适配时尚套装、毛衣/针织衫、时段预售、2人拼单、大陆包邮港澳台不发及不开通额外服务。缺少已有运费模板或页面未提供可核对地区规则时停止，不修改共享运费模板。不同后台结构须检查后适配，不能取第一个控件或默认值。

详情固定17张：有尺码图时首位放一次，保留现有详情，再循环主图补齐；没有尺码图也可运行。原文件不修改。白底图、标签、视频等选填素材没有就跳过；标签如存在且合格才使用，要求1:1或3:4、宽高均大于480px、少于3MB，不合格选填素材提示后跳过。实际页面新增必填项仍会阻断。存在无法处理的详情文字时明确报错。

入口等待页面自身商品初始化完成并稳定，再通过本地上传交互选择图片，不能只等标题框出现。主图每秒核对数量和安全状态；类目兼容自动跳转，联动属性等待实际控件出现。窄窗口及已滚动文档均通过原生横纵滚动显示目标。服务展开、模板显示值及折扣输入按真实DOM读取。入口临时主图地址会被转换，保存前后比较编辑页地址与顺序。

保存前写入不可重复的pending意图，属性、SKU、服务、素材及顺序全部在保存前核对，随后必须看到本次草稿成功提示才标confirmed，不再重新打开草稿。回执分别记录保存前核对结果和本次成功提示。普通模式未知结果阻断重跑；2026-10-22用户明确要求显式“重新创建草稿”优先，重建使用新attempt并沿用本店工作页进入空白新建，不受旧待核实状态拦截，原任务证据及回执保留；不删除旧记录，不把平台预分配ID当保存证据。所有正式发布按钮被驱动拒绝。

## 检查及边界

已实店验证的旧分段模块：10张主图、15项属性、3款式×4尺码、价格库存编码及预览图、商品视频、白底图、时段预售10天、17张详情（尺码仅一次；同回执重跑未追加）。这些分段不等于整单保存验收。

本地命令：npm run check、npm test、npm run test:native、node scripts/check-pdd-dom.mjs、node scripts/check-pdd-navigation.mjs、node scripts/check-pdd-optional.mjs、node --test scripts/check-pdd-media.mjs。原生检查使用隔离数据，不向商家写入。区分本地回归、源码执行器实店验证、已安装App检查和用户从App发起验收；不可互相替代或为重跑删除意图。

App通过本地events.jsonl逐行读取当前步骤，避免Ego控制台在脚本结束后才返回；控制台两路输出仍保留，事件按序号去重。

## 0.4.4 图片与工作页

每店固定一个工作页，显式重建和保存回读均复用；首次或已登记页确实关闭时才补建。原先已积累的其他页面不自动关闭。

商品行直接一键编号并同步SKU/例外调整图片引用；首图按钮旁就地展开缩略图，只选择一张，Excel基础信息仅新增“首图编号”。配置后 sourceMainImages 保留原图与编号，mainImages 表示10个上传槽位；详情在尺码图后从同一张首图开始循环补齐17张。原图需要重复上传时用任务目录的唯一文件名副本，逐槽核对冻结原图指纹；SKU仍按 mainImageMap 指向原文件，不能按重排后轮播位置映射。没有首图配置的旧表继续沿用原详情。

新增检查：node --test test/pdd-image-settings.test.mjs、node scripts/check-image-settings.mjs；只使用临时合成素材，不创建商家草稿。

### v0.4.5批量上传与视频

图片区域一次调用原生多文件选择：详情使用任务缓存01～17独立文件，原库保持5～6张原图与选填尺码表即可。通过原生FileList捕获的原图解码签名，批量比对服务端各位置内容与比例；不会以文件数代替首图检查。商品视频在编辑页就绪时仅提交一次，不阻塞后续填表；守卫顺便检查错误，最终统一等待确认，保存前必须有全部素材confirmed回执。网页操作仍按顺序执行，不并发点击、滚动或输入。

### v0.4.7 数据读取和两类商品

workbook-layout按字段与列标题发现区块，内存兼容旧核心坐标；支持删空行、移动行列和工作表改名后按内容识别，源Excel不重排。首图写回同样跟随实际字段/数据列。没有首图配置且没有详情目录时默认自然首图，循环10/17，不要求补回控制行。

套装区间字段与针织衫具体材质成分分别处理；后者按官方复合控件原生勾选、输入、失焦后数值回读，默认通用数字码缺少字母尺码时切换真实中国码。款式图提交串行，平台处理重叠，最后统一等待内容回执；保存前完整复核仅一次，保存后只确认本次草稿成功提示。

精简表只保留折扣值，按已观察到的满2件固定规则生成运行配置，源文件不加冗余开关；旧显式控制保留优先级。真实缺失、歧义数据、其他类目和新必填项继续明确停止。

### v0.4.14 Windows详情兼容测试

Windows多图副本使用系统TEMP浅目录并限制路径长度；任务回执继续保存在原attempt。详情以5＋5＋5＋2追加，每批校验累计数量、原前缀、内容和顺序；使用同一工作页，每批重新定位详情input。选择后核对FileList字节和浏览器解码尺寸，保留副本路径与具体平台尺寸错误。失败/未知不重传且保留临时副本；全部成功后清理。主图10张和视频与填表重叠逻辑保留。旧的详情一次17张说明仅适用于早期版本；Mac安装版仍0.4.11。本版未通过Windows商家实机验收。
